# AnonLink

Анонимный чат: случайный подбор собеседника — в том числе с фильтрами — и прямой контакт по
User ID. Регистрации нет: при первом открытии сайта браузер получает **анонимную личность** с
публичным User ID. Никаких имён, телефонов, e-mail и адресов проект не спрашивает и не хранит,
а переписка по умолчанию живёт только в оперативной памяти и исчезает вместе с чатом. Владелец —
и только он — может включить архив переписки: см. [раздел ниже](#архив-переписки-только-для-владельца).

> **Статус.** Это работающий MVP с пройденными автоматическими проверками (модульные,
> интеграционные и браузерные тесты, сборка, линт, типы). Он **не** объявляется готовым к
> публичному запуску: не проведены нагрузочные испытания, проверка безопасности сторонними
> специалистами, настройка резервного копирования, мониторинга и HTTPS. Подробно — в
> [docs/COMPLIANCE.md](docs/COMPLIANCE.md) и [docs/SECURITY.md](docs/SECURITY.md).

## Быстрый старт

Нужен Windows 10/11, Node.js 22.12+ и установленный PostgreSQL (локально, службой). Один раз
выполните:

```powershell
cd D:\Projects\HideLink
pnpm setup
```

`pnpm setup` сам: проверит Node.js, создаст `.env` из `.env.example`, установит зависимости,
проверит PostgreSQL и подскажет точную команду, если служба не запущена, создаст базу и применит
миграции, соберёт проект. Повторный запуск безопасен — данные не удаляются.

Затем запустите приложение:

```powershell
pnpm dev
```

и откройте <http://localhost:3000>. Остановить — `Ctrl+C` в том же окне.

Если что-то пошло не так, одна команда покажет полный отчёт о состоянии окружения:

```powershell
pnpm diagnose
```

## Что уже работает

**Личность и приватность**
- Анонимная личность создаётся автоматически; публичный User ID вида `AL7KM3-9PQ2-XRZ4` стабилен
  между перезагрузками страницы (пока жива cookie-сессия).
- Кнопка «Новый ID» мгновенно отзывает все прошлые сессии и выдаёт новую личность: старый User ID
  перестаёт что-либо значить.
- User ID — это публичный идентификатор, а не пароль: зная его, нельзя прочитать переписку,
  занять личность или увидеть, что человек о себе указал.

**Случайный поиск с фильтрами**
- Настройки поиска находятся на отдельной вкладке **до** начала поиска: пол, возраст, город/регион,
  язык общения, «кого искать» и разрешение на смягчение фильтров.
- Фильтры применяются **на сервере** и с двух сторон: подобрать могут только того, кто подходит вам,
  и только если вы подходите ему. Незаполненное значение никогда не считается подходящим.
- Все данные о себе (пол, год рождения, город, языки) — добровольные и непроверяемые; собеседнику
  они не показываются.
- Экран поиска показывает, какие фильтры применяются **на самом деле** (по данным сервера), сколько
  вы ждёте и когда начнётся смягчение.
- Смягчение — только по вашему разрешению, по одному фильтру, с явным сообщением, какой именно
  фильтр снят. Молча этого не происходит никогда.

**Чат**
- Переписка в реальном времени, «Следующий», «Завершить», счётчик длины сообщения, ограничение на
  длину и частоту.
- Собеседник в случайном чате не видит ваш User ID — только вымышленное имя на время разговора.
- Разрыв связи помечается как «соединение потеряно», а не как выход: чат восстанавливается сам.
- Сервер — единственный источник правды о состоянии чата; повторные нажатия и «догоняющие» события
  не создают второй чат и не дублируют сообщения.

**Прямой контакт по User ID**
- Проверка формата, понятные состояния: неверный формат, пользователь не найден, недоступен,
  заявка отклонена, вас заблокировали.
- Заявки принимаются или отклоняются вручную; счётчик до истечения заявки.
- Настройка «Принимать заявки / Не принимать» — проверяется на сервере.
- Заявку нельзя отправить самому себе; частые поиски по User ID ограничены, чтобы перебором не
  искали существующие идентификаторы.

**Безопасность и порядок**
- Блокировка собеседника, в том числе выход из чата одним нажатием; блокировка действует и после
  переподключения.
- Жалоба на собеседника (диалог завершается) с хранением фрагмента переписки для разбора.
- Мат, спам и флуд ограничиваются лимитами; все входящие данные строго проверяются.

## Что осознанно не сделано

- **Медиа** (фото, видео, голосовые) — не реализовано, архитектура к этому подготовлена; смотреть
  `docs/PRODUCT_SPEC.md`.
- **Друзья/контакты** — базовая защита (блокировки, жалобы, добровольное раскрытие User ID в личном
  чате) есть, полноценный список контактов и заявок в друзья — нет.
- **Модерация** — жалобы и блокировки работают полностью, но консоли модератора нет: жалоба
  сохраняет одно сообщение, на которое пожаловались, и ничего больше. Страница владельца `/admin`
  умеет читать архив, но не банить и не разбирать жалобы.
- **Монетизация** — только архитектурная готовность, никакой рекламы и платных функций в интерфейсе.
- **Мультисерверность** — приложение рассчитано на один процесс; очередь подбора — в памяти. Что
  именно нужно изменить для нескольких серверов, описано в `docs/ARCHITECTURE.md`.

## Архив переписки (только для владельца)

По умолчанию чат ничего не сохраняет. Владелец может включить архив — тогда сообщения тех чатов,
которые он выбрал, сохраняются в базе. Пользователям об этом ничего не сообщается.

1. Сгенерируйте ключ:

   ```powershell
   node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
   ```

2. Откройте файл `.env` в корне проекта и впишите полученную строку в `ADMIN_TOKEN`: уберите `#` в
   начале строки и вставьте значение между кавычками. Ключ — это пароль, не пересылайте его и не
   публикуйте.
3. Перезапустите приложение (`pnpm dev`).
4. Откройте **http://localhost:3000/admin** и введите ключ.
5. На странице: включите хранение, выберите **кого** записывать (всех / по параметрам / выбранных
   пользователей), **что** записывать (текст, а типы вложений — на будущее) и **сколько дней**
   хранить (`0` — хранить, пока не удалите сами).
6. Там же сохранённые переписки читаются и удаляются; есть отдельные кнопки «Удалить просроченное» и
   «Удалить всё».

Выключение действует сразу: новые сообщения перестают записываться, уже сохранённое остаётся, пока
не выйдет срок или вы его не удалите.

Если `ADMIN_TOKEN` не заполнять, архив выключен и страницы `/admin` не существует вовсе — это
безопасное состояние по умолчанию.

> **Важно.** Сохранённые переписки лежат в базе **открытым текстом**. Тот, кто получит доступ к базе,
> к её резервной копии или к ключу, прочитает их. Что сделано и что не сделано для защиты — в
> [docs/SECURITY.md](docs/SECURITY.md), раздел 13.

## Структура проекта

```
apps/api          сервер: REST + WebSocket, подбор, чаты, модерация, архив владельца, PostgreSQL
apps/web          веб-приложение (Next.js): все экраны интерфейса
packages/shared   общие правила: фильтры, смягчение, проверки, форматы (тестируются отдельно)
packages/protocol контракты событий WebSocket
tests/e2e         браузерные тесты Playwright (два независимых браузера)
scripts           pnpm setup / pnpm diagnose — понятные человеку проверки окружения
infrastructure    локальная база, примеры конфигурации для сервера (не проверены)
docs              документация
```
